# CPU权重卸载：cpu_offload_gb

## 1. 验证对象与结论

`cpu_offload_gb`允许把部分模型权重存放在CPU内存，计算时再送回NPU，减少NPU内存占用。0表示不卸载，4表示最多允许卸载4 GB；实际卸载量受模型大小等因素影响。模型计算仍在NPU，参数不改变模型公式。

**参数结论：NPU需要；本次完成一行NPU锁页内存分配适配，在保留所测prefill/decode NPU图、关闭`enable_torch_compile`的配置下，基础卸载功能验证通过。**

**参数直接证据：**四组各20条正式请求，共80条，全部完成。两种图配置内，卸载0与4的转写逐条一致；四组转写也相同，各为2/216次词编辑。加载阶段NPU内存从1.63 GB降至0.78 GB，证明卸载生效且未新增所测文字差异。卸载引入搬运开销，图开且编译关时，中位耗时0.171→0.412秒，不承诺“基本无性能损失”。

**必要开发与作用范围：**SGLang共享`OffloaderV1`创建卸载存储时，在原锁页判断中增加`or device.type == "npu"`。锁页内存是适合设备异步搬运的CPU内存。这一行属于共享NPU内存分配适配，没有修改模型、底层算子的数学实现、原卸载预算或非NPU分配判断。Qwen3-ASR是本次验证载体；该路径的其他NPU模型不能自动视为已验收。

## 2. 测试用例

固定模型和20条输入语音，在两种明确配置下分别比较卸载0和4：先检查请求完成及转写一致性，再看加载/就绪时的NPU内存和时间开销。图开关与编译开关分别记录，不把配置中的`torch_compile=True`直接当作实际编译已经执行的证据。

### 2.1 环境信息

| 项目 | 实测条件 |
| --- | --- |
| 模型与任务 | Qwen3-ASR-0.6B；16 kHz英语语音转写，BF16 |
| 平台 | 151服务器昇腾NPU；使用已保存历史运行，不在本轮重新启动模型 |
| 软件及源码 | SGLang 0.5.20、PyTorch/torch_npu 2.10；采用上述一行锁页修改的`offloader.py` |
| 固定条件 | 卸载0/4；`max_total_tokens=8192`；同一组20条正式输入，预热不计入20条 |
| 图关闭组 | `cuda_graph=False`；运行配置中`torch_compile=True`，但这组证据没有证明实际进入编译路径，不计为编译功能通过 |
| 图开启组 | 明确设置`cuda_graph=True`、`torch_compile=False`；输入与生成两阶段图均有执行及成功重放记录 |
| 配对方式 | 每种图配置内仅比较卸载0与4；核输入来源、WAV SHA256、参考文字、原始响应和转写结果 |

2026-10-13只读复核重新核对80份正式结果及原始WAV/响应，未重新推理。汇总为`交付补测_20260929/CPU最小作用域复核_20261013/basic_evidence/pin_only_basic_audit.json`。原件分别位于`parallel_evidence_0324/cpu_matrix_v2_o0_g0`、`cpu_matrix_v2_o4_g0`和`delivery_evidence_0403/cpu_graph_compile_false_diag_results`、`cpu_offload4_fullgraph_nocompile_results`，均相对`交付补测_20260929/`，对应配置、日志与文件SHA随审计保存。

四组日志明确记录卸载文件身份，存档注意力后端也与0.5.20原文件一致；本组证据没有每次启动的完整依赖树/内核逐文件哈希清单，因此不声称所有运行依赖均逐文件验过。

| 用例名称 | 用例步骤 | 预期结果 | 实际结果 |
| --- | --- | --- | --- |
| 图关闭、不卸载 | 图关闭，卸载设0，执行固定20条语音 | 请求全部完成，形成对照 | 20/20完成；2/216词编辑；不据编译配置标志声称编译路径通过 |

| 图关闭的延迟与处理速率 | 从两组各20条原始请求时间重算 | 如实记录卸载代价 | 0/4组中位0.498/0.694秒，P95为0.615/0.862秒；顺序请求处理速率1.994/1.445请求/秒 |
| 图开启且关闭编译的延迟与处理速率 | 同上，在显式关闭编译的图执行组计算 | 如实记录卸载代价 | 0/4组中位0.171/0.412秒，P95为0.230/0.516秒；顺序请求处理速率5.719/2.416请求/秒 |
| 默认编译加图问题的独立对照 | 核对原卸载0、图及编译均开启的失败日志 | 区分已有编译兼容问题与卸载引入的问题 | 卸载0也在图捕获时因`PagedAttentionOperation`路径失败，未产生20条成功结果；作为独立编译问题保留，不计入80条基础功能成功数 |

每组2/216约为0.93%的转写词错率；这里只说明开启卸载未新增观察到的文字差异，不是模型零词错。内存是指定时点的记录，不是整个请求周期峰值，也不表示模型恰好卸载4 GB。P95按20条数据的最近秩计算；请求/秒为20除以这20次HTTP请求耗时之和，不含预处理，不是最大并发吞吐或纯解码速度。跨图配置的速度差异也不用于宣称编译加速。

**性能结论：**在相同的图开启、编译关闭配置下，卸载0/4的中位耗时为0.171/0.412秒，体现的是启用卸载的实测时间代价，不能归因于关闭编译。历史编译开启结果使用另一套补丁，不是仅改变编译开关的严格对照；现有证据不能单独量化关闭编译的性能影响，也不支持“基本无性能损失”的结论。本次交付的是有明确配置与性能代价的基础卸载功能。

编译兼容问题的环境、失败条件、卸载0也失败的对照、已知定位和可能修复方向已写入[Issue #43958](https://github.com/sgl-project/sglang/issues/43958)。后续优先修复框架分支、编译调用接口和图重放参数更新，复用原NPU算子的数学实现；历史完整候选的成功结果仅证明方向可行，不代表所有旧改动必要或新的局部方案已验证。
