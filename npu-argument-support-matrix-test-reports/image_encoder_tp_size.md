# 图片编码器张量并行：image_encoder_tp_size

## 1. 验证对象与结论

`image_encoder_tp_size`控制图片编码器由几张NPU共同计算：1表示一张，2表示两张按规则分担同一次图片编码，即张量并行（TP）。它不表示整个Ming模型只用这些卡，回答阶段还使用另外的计算资源。任务清单沿用此参数名；所测版本的配置键及命令行参数分别为`image_encoder.tp_size`、`--image_encoder.tp_size`。

**参数结论：NPU需要；现有TP机制在Ming接入中遗漏了初始化配置传递，本次补齐后，所测多卡加载、真实权重分片与图片问答路径验证通过。另有模型修复及项目选定的数值一致性算法，分别记录，不将整份PR都认定为基础TP支持必需的开发。**

**参数直接修复：**Ming初始化时漏向`ServerArgs`传入实际`tp_size`，造成通信组使用双卡而加载器读取默认单卡。本次补齐配置传递，修复的是模型接入，共享TP机制和底层矩阵算子数学实现未因此改写。TP2完整请求及TP2/4/8局部编码结果支持所测分片路径可用；TP4/8没有完整900题服务评测。

当前PR没有修改共享CANN、TorchNPU或SGLang矩阵内核源码。接入、特征/路由修复和数值算法应分别审查；本报告保留项目选定的新算法及其测量结果，不将其成绩转移给移除算法后的未测版本。

**所选版本的内容验收与性能：**TP2完成900/900题，无请求失败或不可解析回答，确定性审计答对538/900。历史单卡正确的固定532题中保留524题、退化8题，另新增14题正确。按本项目确认的质量范围接受，8道退化及原始失败仍单列保留，不用新增正确题抵销。新算法双卡局部编码耗时约为单卡2.72倍，完整服务吞吐、首字及总响应延迟未测，不能用旧算法的整服务性能补充。

**独立跟踪的问题：**另一次同环境单/双卡八题对照中，两组答案相同、均为1/8正确，对应图片特征、注入数据和首两步生成分数也相同。因此，历史8题退化尚未全部解释，不能统一归为“多卡矩阵算子错误”。Issue #2737记录8个病例的答案、版本与执行条件，继续跟踪差异原因；完整原始输入、结果及诊断材料保留在本地证据归档，未公开上传，可按授权提供。

**源码身份与提交状态：**PR #2427由基线`c508f35afd556a3d588c6d757932e8b4ce2f6d8d`更新至`da3da32dcf3fdc2be41acb96c2b4b6f604739342`。更新涉及3个产品文件及匹配测试，产品计算逻辑与完整900题冻结源码等价，测试仅作等价导入和格式整理。PR包含本文新算法，保持草稿、未合并；没有因报告整理重跑900题，也未将后续研究候选纳入。本报告不代表当前官方发行包已包含修复，主线冲突和上游集成仍待处理。

新旧全量运行不是仅改变算法的严格对照，分数变化不能全部归因于新算法；本报告按选定版本报告观察结果。图配置、各项测试及覆盖边界见下文。

## 2. 测试用例

先核权重是否按配置分片加载、每张卡是否真正参与计算，再比较编码器特征，最后检查真实模型问答。编码器输出一致只证明这一阶段；完整答案还受回答模型、缓存和请求执行条件影响。
